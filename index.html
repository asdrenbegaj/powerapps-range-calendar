A date-range calendar component for Power Apps

The booking calendar from our Asset Booking app, rebuilt as a reusable component. Drop it on a screen, set a few properties, and read the dates back. It marks today, picks a single day or a range, and respects booking rules such as blocked dates and maximum length.

How it works

The formulas below are the real ones from the component. The demo above runs the same rules in JavaScript so you can watch the values change as you click.

01State lives inside the component

Inside a component, Set() doesn't create app-wide variables. Each copy of the component gets its own _month, _start and _end, so two calendars on one screen never interfere, and nothing clashes with variables already in your app.

The app never touches those variables. It reads output properties instead, and clears the calendar with Reset(RangeCalendar1), which runs the component's OnReset.

// cmpRangeCalendar.OnReset
Set(_start, Blank()); Set(_end, Blank()); Set(_month, Blank())

// Output properties (component → app)
StartDate   = _start
EndDate     = If(IsBlank(_start), Blank(), Coalesce(_end, _start))
DayCount    = If(IsBlank(_start), 0,
                 DateDiff(_start, Coalesce(_end, _start), TimeUnit.Days) + 1)
IsComplete  = !IsBlank(_end)

// Month arrows (Previous uses -1)
Set(_month, DateAdd(Coalesce(_month, Date(Year(Today()), Month(Today()), 1)),
                     1, TimeUnit.Months))

0242 days from Sequence(), rules worked out once

A month can touch six different weeks, so the grid is always 6 × 7 = 42 cells and never changes height. Weekday(first, StartOfWeek.Monday) - 1 is how far to step back from the 1st to land on a Monday.

Every "can't pick this day" rule from the input properties is folded into one IsDisabled flag per cell. The button just uses DisplayMode, so disabled days can't be clicked or tabbed to.

// rcDays.Items   (WrapCount = 7)
With(
    { first: Coalesce(_month, Date(Year(Today()), Month(Today()), 1)),
      minD: cmpRangeCalendar.MinDate, maxD: cmpRangeCalendar.MaxDate },
    With(
        { offset: Weekday(first, StartOfWeek.Monday) - 1 },
        ForAll(
            Sequence(42, 0) As n,
            With(
                { d: DateAdd(first, n.Value - offset, TimeUnit.Days) },
                {
                    CalDate: d,
                    InMonth: Month(d) = Month(first),
                    IsToday: d = Today(),
                    IsDisabled:
                        (!IsBlank(minD) && d < minD)
                        || (!IsBlank(maxD) && d > maxD)
                        || (cmpRangeCalendar.DisableWeekends
                            && Weekday(d, StartOfWeek.Monday) > 5)
                        || d in cmpRangeCalendar.BlockedDates.BlockedDate
                }
            )
        )
    )
)

03One button per cell, styled from state

Each cell is a single button. Fill asks: is this the start or end day? Is it in between? Coalesce(_end, _start) treats a half-finished selection as one day, so the start lights up straight away.

Colours come from one input, AccentColor. ColorFade() makes the lighter "in between" and hover shades from it, so re-theming is a one-property change.

Today gets a ring through BorderThickness, so it still shows when it's selected.

// rcDay.Fill
With(
    { s: _start, e: Coalesce(_end, _start), d: ThisItem.CalDate },
    If(
        !IsBlank(s) && (d = s || d = e), cmpRangeCalendar.AccentColor,
        !IsBlank(s) && d > s && d < e,   ColorFade(cmpRangeCalendar.AccentColor, 0.88),
        RGBA(0, 0, 0, 0)
    )
)

// rcDay.BorderThickness
If(ThisItem.IsToday, 2, 0)

// rcDay.DisplayMode
If(ThisItem.IsDisabled, DisplayMode.Disabled, DisplayMode.Edit)

04The selection rule

The whole selection logic comes down to one sentence: if this click can't finish a valid range, it starts a new one.

  1. Click any available day: it becomes the start.
  2. Click the start or a later day: it becomes the end.
  3. Click an earlier day, or one that would make the range too long or cross a blocked day: it becomes the new start.
  4. Click any day once a range is set: start again from there.
  5. Clear or Reset(RangeCalendar1) empties it.

With AllowRange off, every click is a complete one-day selection.

// rcDay.OnSelect
With(
    { d: ThisItem.CalDate },
    If(
        // Single-day mode: every click is a complete selection
        !cmpRangeCalendar.AllowRange,
            Set(_start, d); Set(_end, d),
        // Start a new selection when...
        IsBlank(_start)                       // nothing picked yet
            || !IsBlank(_end)                 // a range is already complete
            || d < _start                     // clicked before the start
            || (cmpRangeCalendar.MaxDays > 0  // range would be too long
                && DateDiff(_start, d, TimeUnit.Days) + 1 > cmpRangeCalendar.MaxDays)
            || CountRows(                     // range would cross a blocked day
                   Filter(cmpRangeCalendar.BlockedDates,
                          BlockedDate > _start && BlockedDate < d)
               ) > 0,
            Set(_start, d); Set(_end, Blank()),
        // ...otherwise finish it (same day = one-day selection)
        Set(_end, d)
    )
)

Using it in your app

Once the component is on a screen, everything happens through its properties. These examples assume the copy is called RangeCalendar1.

ASave a booking

Output properties update by themselves, so a Book button can enable itself as soon as a range is complete, and save the dates directly.

If one click should be enough for a one-day booking, use !IsBlank(RangeCalendar1.StartDate) instead of IsComplete.

// btnBook.DisplayMode
If(RangeCalendar1.IsComplete, DisplayMode.Edit, DisplayMode.Disabled)

// btnBook.OnSelect
Patch(
    Bookings,
    Defaults(Bookings),
    {
        StartDate: RangeCalendar1.StartDate,
        EndDate:   RangeCalendar1.EndDate
    }
);
Reset(RangeCalendar1)

// lblSummary.Text
RangeCalendar1.DayCount & If(RangeCalendar1.DayCount = 1, " day", " days")

BBlock days that are already booked

Bookings are usually stored as start and end dates, but the calendar wants a list of single days. Expand each booking into its days once, when the screen opens or the asset changes, and pass the result to BlockedDates.

Use dates without times (SharePoint "Date only" columns, Today(), Date()), or the matching won't line up.

// e.g. galAssets.OnSelect or Screen.OnVisible
Clear(colBlocked);
ForAll(
    Filter(Bookings, AssetID = varAsset.ID, EndDate >= Today()) As b,
    Collect(
        colBlocked,
        ForAll(
            Sequence(DateDiff(b.StartDate, b.EndDate, TimeUnit.Days) + 1, 0) As i,
            { BlockedDate: DateAdd(b.StartDate, i.Value, TimeUnit.Days) }
        )
    )
)

// RangeCalendar1.BlockedDates
colBlocked

CSet the rules

Every rule is an input property on the copy you placed. They can be fixed values or formulas, for example a booking limit read from a Settings list.

RangeCalendar1.MaxDate         = DateAdd(Today(), 90, TimeUnit.Days)
RangeCalendar1.MaxDays         = LookUp(Settings, Title = "MaxBookingDays").Value
RangeCalendar1.DisableWeekends = true
RangeCalendar1.AccentColor     = ColorValue("#007f3b")

Two calendars, one screen

Each copy keeps its own selection, so "loan dates" and "return inspection" pickers can sit side by side.

One place to fix it

From a component library, a change to the calendar is offered to every app that uses it the next time they're edited.

Date-only maths

Everything uses Today() and Date(), never Now(), so nothing drifts a day when the clocks change.

No event property needed

Outputs recalculate on their own, so the app reacts without OnChange. Custom event properties are still experimental in Power Apps, so the component avoids them.
